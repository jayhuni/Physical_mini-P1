# 자리 설명용 대본 (3분)

강사님이 자리에 오셨을 때 대시보드 화면 하나로 설명하는 순서다. 정식 발표용 10분 구성은 [presentation.md](presentation.md)에 있다.

## 미리 켜 둘 것
1. 터미널에서 `.\.venv\Scripts\python app.py`를 실행하고 브라우저에서 http://127.0.0.1:8050 을 연다.
2. 탐색기에서 `output/` 폴더를 열어 둔다. 질문이 나오면 보여 준다.

## 설명 순서

| # | 화면에서 할 것 | 할 말 |
|---|---|---|
| 1 | 맨 위 요약 카드를 가리킨다 | "시설 3곳 로그를 합쳐서 검사 5,198건, 불량 238건, 불량률 4.58%입니다. `python main.py` 한 줄이면 같은 결과가 `output/`에 CSV·그래프·요약으로 저장됩니다." |
| 2 | 시설에서 **B시설**을 고르고 날짜를 **11/18 하루**로 바꾼다 | "선택을 바꾸면 숫자·그래프·표가 같이 바뀝니다. 집계는 `aggregator.py` 한 곳에서만 해서 CSV와 화면 숫자가 어긋나지 않습니다." |
| 3 | 선택을 비우고 **불량 급증 탐지** 표까지 내린다 (O2) | "그날을 뺀 평소 불량률로 기대 건수를 계산해서 5건 이상, 3배 이상, 우연일 확률 0.0001 이하면 급증으로 잡습니다. 데이터에서 눈으로 찾은 3건(A-CAM1 11/20 판정 불가, C시설 11/19 치수 초과, B시설 11/18 이물)이 그대로 잡혔고, 다른 오탐은 없었습니다." |
| 4 | **D99를 불량에서 제외** 체크박스를 켠다 | "A-CAM1 11/20의 판정 불가 11건은 불량이라기보다 장비 이상입니다. 빼면 불량 227건, 4.37%가 됩니다. 검사는 했으니 검사 수에는 남깁니다." |
| 5 | **불량 박스 분석** 히트맵·산점도를 보여 준다 (O1) | "박스 227건의 중심이 모두 사진 가운데에 모여 있고 특정 위치에 몰리지는 않습니다. 위치로는 원인을 좁힐 수 없다는 것도 결론입니다. 잘못된 좌표는 0건입니다." |

## 질문이 오면 (한 줄 답)

| 질문 | 답 |
|---|---|
| 기준값(0.0001)은 어떻게 정했나? | 처음엔 0.001이었는데 무작위 데이터에서 오탐이 나와 30회 시뮬레이션으로 강화했습니다 ([ADR-002](decisions/ADR-002-spike-criterion.md)). |
| 왜 그날을 빼고 '평소'를 구하나? | 넣으면 급증한 값이 평소를 끌어올려서 급증이 스스로를 가립니다. |
| 불량 종류를 고르면 불량률이 100%가 되지 않나? | 분모(검사 수)는 시설·날짜로만 거르고, 분자만 불량 종류로 제한합니다. |
| 화면 쪽에 집계 코드가 없다는 건 어떻게 보장하나? | `app.py`에 `groupby` 등이 있으면 테스트(`test_d7_app_has_no_aggregation_code`)가 실패합니다. |
| 테스트는? | 64개입니다. 기대값은 손으로 계산했고, 고도화 기능은 테스트를 먼저 썼습니다. |
| AI는 어떻게 썼나? | 요청·결과·검증·직접 확인한 내용을 [AI_USAGE.md](../AI_USAGE.md)에 기능별로 남겼습니다. |
| 팀 협업은? | 작업 전 `scripts/sync_check.sh`로 main·팀원 브랜치와 겹치는 파일을 먼저 확인하고, PR은 squash merge합니다 ([collaboration.md](collaboration.md)). |
