# 2026-11-24 D99(판정 불가) 제외 불량률 옵션

- 관련 요구사항: F4~F7, F10, F11, D3~D6 / TEAM_README 남은 작업

## 문제
로그에서 판정 불가(D99)도 `NG`로 기록되어 항상 불량으로 셌다. 하지만 D99는 제품 결함이 아니라 카메라·시스템이 판정을 못 한 것이다. A-CAM1처럼 D99가 몰린 카메라는 실제 품질보다 불량률이 높게 보인다. 두 관점을 모두 볼 수 있어야 한다.

## 판단
- **분모에는 남기고 분자에서만 뺀다.** 검사는 수행했으므로 검사 수에 포함한다. 분모에서도 빼면 "판정된 검사 중 불량률"이 되어 기존 수치와 비교 기준이 달라진다.
- **불량률 집계에만 적용한다.** 전체 로그는 원본 그대로 저장한다. 이상 기록(F8)과 급증 탐지(O2)도 D99를 계속 포함한다. D99 자체가 시스템 이상 신호이기 때문이다(예: A-CAM1 11/20 급증).
- **구현은 데이터 단계 한 곳에서 한다.** 모든 집계 함수에 인자를 추가하는 대신 `apply_d99_policy(df)`가 D99 행의 `result`를 `UNDETERMINED`로 바꾼 복사본을 만든다. 기존 집계 함수는 `result == "NG"`만 세므로 수정 없이 동작한다. 바뀌는 함수가 없어 영향 범위가 작다.
- **기본값은 기존 동작(포함)으로 둔다.** 과제 제출 결과(5,198건 / 238건 / 4.58%)가 바뀌지 않는다.

## 한 일
- `aggregator.apply_d99_policy`, 상수 `UNDETERMINED_RESULT`
- `config`: `count_d99_as_defect`(기본 true), `--exclude-d99`
- `main.py`: 불량률 집계에는 정책을 적용한 로그를 쓰고, 요약에 "판정 불가(D99): 불량에 포함/제외" 줄 추가
- `app.py`: 컨트롤 줄 끝에 체크박스. 초기값은 설정을 따른다
- README(설정·실행 예·집계 기준), TEAM_README, AI_USAGE

## 검증
- 테스트 4개를 먼저 작성해 실패 확인 → 구현 → **48 passed, 6 skipped**
- 합성 데이터(D99 11건 포함)로:
  - `python main.py --exclude-d99` → 불량 188 → 177건, 3.80% → 3.58%. 요약에 기준 표시. 이상 기록 573건과 급증 10건은 그대로
  - `python app.py`를 띄워 HTTP로 콜백을 호출(A시설 선택): 체크 해제 시 불량 60건·3.33%, 체크 시 49건·2.72%. 검사 수 1,800건, 이상 기록 212건, 급증 3건은 양쪽 모두 같음
- **실제 데이터 수치는 제공 데이터를 넣고 다시 확인한다.** 실제 D99 건수만큼 238건에서 줄어야 한다

## 협업 메모
- hotspot 파일(`app.py`, `main.py`, `config.py`)은 구역 끝에 추가했다. 컨트롤은 줄 끝, 콜백 Input과 `build_view` 인자는 맨 뒤에 기본값과 함께 추가했다
- `build_view`의 새 인자는 기본값이 있어 기존 호출과 테스트가 그대로 동작한다

## 포트폴리오 포인트
- 도메인 판단("판정 불가는 불량인가?")을 **설정 하나로 전환**할 수 있게 했다. 모든 집계 함수를 고치지 않고 **데이터 정책 함수 한 곳**에서 처리해 변경 범위를 최소화했다. 이상 탐지 쪽 의미는 보존했다.
