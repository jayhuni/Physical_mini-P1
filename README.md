# 비전검사 로그 통합 처리 프로그램

세 시설(A, B, C)의 비전검사 로그 CSV를 하나로 합치고, 불량을 종류별로 집계해 CSV·그래프·요약으로 저장하며, 웹 대시보드(Dash)로 조건을 바꿔 가며 볼 수 있는 프로그램이다. 과제 명세는 [비전검사_로그_통합_처리_프로그램_개발.md](비전검사_로그_통합_처리_프로그램_개발.md)에 있다.

## 해결한 문제

시설마다 검사 로그 파일이 따로 있어 전체 품질 현황을 한눈에 볼 수 없었다. 이 프로그램은 다음을 한다.

- 시설 로그를 모두 합치고, 불량을 시설·종류·분류·날짜·카메라별로 집계한다 (필수 F1~F11)
- 같은 집계 함수로 웹 대시보드를 띄워 조건을 바꿔 가며 본다 (D1~D7)
- 평소보다 불량이 크게 늘어난 날·시설·카메라를 자동으로 찾는다 (선택 O2)
- 불량 박스의 크기와 사진 안 위치 분포를 정리한다 (선택 O1)

## 제공 데이터 처리 결과

2026-11-16 ~ 11-20, 시설 3곳, 카메라 5대의 로그를 처리한 결과다. 숫자는 `python scripts/final_check.py`로 다시 확인할 수 있다.

| 항목 | 값 |
|---|---|
| 전체 검사 / 불량 / 불량률 | 5,198건 / 238건 / 4.58% |
| 불량률 최고 시설 | A시설 5.14% (B시설 4.14%, C시설 4.31%) |
| 최다 불량 종류 | 스크래치 77건 |
| 이상 기록 (판정 불가 또는 처리 시간 1000ms 초과) | 11건 |
| 판정 불가(D99)를 불량에서 빼면 | 227건 / 4.37% |

데이터에서 발견한 것:

1. **A-CAM1 11/20 판정 불가 11건**: 다른 날에는 0건이다. 처리 시간 5000ms, 신뢰도 0으로 불량이 아니라 장비 이상으로 보인다.
2. **C시설 11/19 치수 초과 21건**: 평소 기대 3.74건의 5.6배이고, 카메라 두 대 모두 늘었다. 카메라보다 공정 쪽 원인이 의심된다.
3. **B시설 11/18 이물 15건**: 평소 기대 3.01건의 5.0배이고, B시설의 5일간 이물 27건 중 절반 이상이 이날 나왔다.
4. **불량 위치**: 박스 227건의 중심이 모두 사진 가운데(x 381~940, y 279~750)에 있고 특정 칸에 몰리지 않았다. 위치로는 원인을 좁힐 수 없다. 잘못된 좌표는 0건이다.

1~3은 급증 자동 탐지(O2)가 찾은 결과와 같다. 탐지 기준으로 다른 오탐은 나오지 않았다.

## 구조

```
input/*.csv ──> loader ──> aggregator · spike · box ──┬──> main.py ──> output/ (CSV, PNG, summary.txt)
               (읽기·병합)  (집계 · 급증 · 박스)           └──> app.py  ──> 웹 대시보드
config.json + 명령 인자 ──> config        plotter(PNG)  exporter(저장·로그)
```

집계는 `aggregator`·`spike`·`box`에서만 한다. 파일 출력과 화면이 같은 함수를 쓰므로 두 곳의 숫자가 어긋나지 않는다. 화면 파일(`app.py`)에 집계 코드가 없다는 것은 테스트로 확인한다.

## 필요한 패키지와 설치

Python 3.15.2, pandas 3.1.1, matplotlib 3.11.2, dash 4.5.1 에서 개발하고 검증했다. 다른 버전은 확인하지 않았다.

```bash
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

그래프의 한글은 설치된 한글 글꼴(Malgun Gothic, AppleGothic, NanumGothic 등)을 자동으로 찾아 쓴다. 한글 글꼴이 하나도 없는 PC에서는 `fonts/`에 동봉한 나눔고딕(SIL OFL)을 등록해 쓰므로 한글이 깨지지 않는다.

## 데이터 준비

저장소에는 제공 데이터와 처리 결과를 올리지 않았다. 프로젝트 폴더에 `input/` 폴더를 만들고 아래 4개 파일을 직접 넣는다. 입력 폴더는 `config.json`의 `input_dir`(기본: `input`)이다.

```
input/
├── defect_codes.csv
├── facility_A_log.csv
├── facility_B_log.csv
└── facility_C_log.csv
```

`facility_`로 시작하는 CSV는 파일 이름이나 개수에 상관없이 모두 읽으므로 시설 로그가 늘어도 코드를 고칠 필요가 없다.

## 실행 방법

### 1) 전체 처리 (명령 한 줄)

```bash
python main.py
```

결과는 `output/` 폴더에 저장되고 요약은 화면에도 출력된다.

설정을 바꿔 실행하는 예:

```bash
# 입력/출력 폴더와 이상 기록 기준값(ms) 지정
python main.py --input-dir data --output-dir result --threshold 800

# 조건 필터 (F9): A시설, 11/17 이후, 스크래치와 판정 불가만
python main.py --facility A시설 --start-date 2026-11-17 --defect 스크래치 D99

# 판정 불가(D99)를 불량률 집계에서 불량으로 세지 않기
python main.py --exclude-d99
```

### 2) Dash 화면

```bash
python app.py
```

브라우저에서 http://127.0.0.1:8050 을 연다. 로그는 앱을 시작할 때 한 번만 읽는다.

- 위쪽 선택: 시설(여러 개), 날짜 범위, 불량 종류, 판정 불가(D99) 제외 체크박스
- 선택을 바꾸면 다시 계산되는 것: 요약 숫자, 시설별 불량 종류 막대그래프, 날짜별 불량률 꺾은선그래프, 시설 × 불량 종류 표, 이상 기록 표, 불량 급증 표(O2), 불량 박스 표·위치 히트맵·중심점 산점도(O1)

### 3) 테스트

```bash
python -m pytest tests -q
```

### 4) 제출 전 최종 점검과 압축

```bash
python scripts/final_check.py       # 테스트, 처리, 기대 수치, 급증 3건, 박스 분석, 화면 계산을 한 번에 점검
python scripts/make_submission.py   # dist/ 에 코드 압축(데이터·결과 제외)과 결과 압축 생성
```

## 설정 항목

[config.json](config.json)에 적고, 같은 항목을 명령 인자로 주면 명령 인자가 우선한다.

| 항목 | 명령 인자 | 기본값 | 설명 |
|---|---|---|---|
| `input_dir` | `--input-dir` | `input` | 시설 로그와 불량코드표가 있는 폴더. 설정 파일이 없을 때의 코드 기본값은 `.` |
| `output_dir` | `--output-dir` | `output` | 결과 저장 폴더. 없으면 자동 생성 |
| `process_ms_threshold` | `--threshold` | `1000` | 이 값(ms)을 **넘는** 기록을 이상 기록으로 분류 |
| `facility_file_prefix` | - | `facility_` | 시설 로그 파일 이름 접두어 |
| `defect_codes_file` | - | `defect_codes.csv` | 불량코드표 파일 이름 |
| `csv_encoding` | - | `utf-8-sig` | 저장 CSV 인코딩. BOM 포함이라 엑셀에서 한글이 깨지지 않는다 |
| - | `--facility` | 없음 | F9 필터: 시설 이름 (여러 개 가능) |
| - | `--start-date` `--end-date` | 없음 | F9 필터: 날짜 범위 (양 끝 날짜 포함) |
| - | `--defect` | 없음 | F9 필터: 불량 코드 또는 이름 (여러 개 가능) |
| `spike_min_count` | - | `5` | O2 급증: 그날 불량이 이 건수 이상 |
| `spike_ratio` | - | `3.0` | O2 급증: 평소 기대 건수의 이 배수 이상 |
| `spike_max_p` | - | `0.0001` | O2 급증: 평소 수준에서 우연히 나올 확률(포아송)이 이 값 이하 |
| `count_d99_as_defect` | `--exclude-d99` | `true` | 판정 불가(D99)를 불량률 집계의 불량으로 셀지. Dash에서는 체크박스로 바꾼다 |
| `image_width` / `image_height` | - | `1280` / `1024` | O1: 검사 사진 크기(px). 이 범위를 벗어난 박스는 잘못된 좌표로 제외 |
| `box_grid_cols` / `box_grid_rows` | - | `4` / `4` | O1: 위치 분포를 셀 격자 칸 수 |

## 집계 기준

- **불량**은 `result`가 `NG`인 기록이다. 판정 불가(D99)도 `NG`로 기록되어 있어 불량 수에 포함한다. D99는 이상 기록에서도 별도로 분류된다.
- `--exclude-d99`(또는 `count_d99_as_defect: false`)를 주면 D99는 **검사 수에는 남고 불량 수에서만 빠진다**(검사는 했지만 불량으로 판정한 것은 아니므로). 영향을 받는 것은 불량률 집계(F4~F7, 그래프, 요약)뿐이다. 전체 로그·이상 기록·조건 필터·급증 탐지는 원본 기준이다. 요약 파일에 어느 기준으로 집계했는지 표시된다.
- **이상 기록**은 D99이거나 `process_ms`가 기준값을 **초과**한 기록이다. 기준값과 같은 값은 포함하지 않는다.
- Dash에서 불량 종류를 고르면 검사 수(분모)는 시설·날짜 조건으로만 정해지고, 불량 수(분자)만 선택한 종류로 줄어든다.
- **불량 급증(O2)**: 같은 시설(또는 카메라)·같은 불량 종류에서 **그날을 뺀 나머지 날의 불량률**을 평소로 보고, `평소 불량률 × 그날 검사 수`를 기대 건수로 삼는다. 그날 불량이 ① 5건 이상, ② 기대 건수의 3배 이상, ③ 평소 수준에서 우연히 나올 확률(포아송) 0.0001 이하이면 급증이다. 건수가 아니라 불량률로 비교하므로 검사를 많이 한 날은 급증으로 잡히지 않는다. 기준을 정한 이유와 시뮬레이션 결과는 [docs/decisions/ADR-002-spike-criterion.md](docs/decisions/ADR-002-spike-criterion.md)에 있다.
- **불량 박스(O1)**: NG이면서 D99가 아니고 좌표 4개가 모두 있는 기록만 쓴다. 중심점 = ((x1+x2)/2, (y1+y2)/2), 면적 = (x2−x1)×(y2−y1). 좌표가 사진 밖이거나 x2≤x1, y2≤y1이면 분석에서 빼고 `run_log.txt`에 건수와 일련번호를 남긴다. 위치 분포는 박스 **중심**이 들어간 칸으로 센다(경계는 오른쪽·아래 칸).
